## 원격 검증

HTTPS 200 응답과 Chrome에서 첫 화면을 확인했습니다. 배포 서버를 대상으로 `test/integration.mjs`를 실행해 다음 항목을 통과했습니다.

- 비인증 요청 및 다른 Origin 요청 거부
- 독립된 두 브라우저 세션에 해당하는 참가자 입장
- WebSocket 상태 동기화와 상대 카드 비공개
- 오래된 상태의 행동 거부
- 한 핸드 전체 진행과 칩 보존
- 방별 랭킹과 핸드 결과 저장
- 연결을 끊고 재접속한 뒤 기록 유지
- 방장 퇴장 시 다음 참가자에게 역할 이전

Chrome에서 320×568, 390×844, 667×375, 844×390, 1366×768, 1440×900 화면과 키보드 조작, 오프라인 복구를 검수했습니다. Mac Safari에서 방 생성, 연결과 초대 링크 복사도 확인했습니다. 실제 iOS, Android 및 Windows 기기 검증과 기기 간 동일 계정 연동은 포함하지 않습니다. 상세 결과는 [기기별 검수](device-qa.md)를 참고하세요.

원격 검증용 방에는 `검증 A`, `검증 B` 이름의 테스트 참가 기록만 생성했습니다. 해당 무작위 초대 코드는 공개하지 않았으며 사용자의 게임 기록과 분리되어 있습니다.

## 비용 범위

무료 플랜의 일별 한도를 넘으면 요청이 제한됩니다. 무제한 무료 운영을 보장하지 않습니다. 계정 요금제가 향후 유료로 변경되면 그 요금제의 과금 정책을 따릅니다.

## 사용 방법

닉네임과 방 이름 입력 → 새 테이블 만들기 → 친구 초대 → 친구에게 링크 전달 → 2명 이상 준비하기 → 방장이 첫 핸드 시작.

랭킹을 이어가려면 같은 방 링크로 다시 모입니다. 참가자 신원은 브라우저 쿠키에 연결되므로 쿠키 삭제나 다른 기기 접속 시 별도 참가자로 처리됩니다.
