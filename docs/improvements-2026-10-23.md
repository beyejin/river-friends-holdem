# RIVER 화면과 기록 개선

작업일: 2026-10-23

기존 바닐라 JavaScript 화면과 Cloudflare Worker 및 SQLite Durable Object 구조를 유지했습니다. `src/poker.js`의 게임 엔진은 변경하지 않았습니다. 로컬 검증 후 운영에 배포했으며, 기존 회원 8명과 수동 게임 기록 1개의 저장 원문을 보존한 것을 확인했습니다. 배포 후 기록 수정과 테스트 데이터 정리 결과는 [이번 배포 기록](deployment-2026-10-23.md)에 정리했습니다.

## 화면과 이용 흐름

- 중앙의 장식용 이미지 스타일을 제거하고 홈을 작은 테이블 열기 영역과 주간 랭킹으로 구성했습니다.
- 홈에서 주간 우승순과 누적 리바인순을 선택할 수 있습니다. 주요 입력은 16px, 주요 버튼은 높이 44~48px를 확보하고 작은 화면에서는 기록 입력을 세로로 배치합니다.
- 기본 회원은 이름을 선택해 바로 테이블을 엽니다. 새 회원은 기수와 이름으로 등록하고 바로 입장하거나 `등록만 하기`로 나중에 참여할 수 있습니다.
- 최대 9명, 시작 및 리바인 칩 30,000, 블라인드 150/300과 기존 실시간 게임 흐름을 유지했습니다.
- 가이드에는 카드 예시가 있는 홀덤 족보, 프리플랍 시작패 순위와 분류, 게임 방법 탭을 추가했습니다. 시작패 순서는 입문용 참고이며 참가 인원과 상황에 따라 달라진다는 설명과 출처를 함께 표시합니다.

## 지난 게임 기록

홈의 `지난 게임 기록`에서 날짜와 참가자 2~9명을 선택하고 회원별 승리 및 리바인 횟수를 입력합니다. 선택하지 않은 회원의 횟수와 시각 입력은 숨기고 비활성화합니다.

리바인 횟수만큼 날짜와 시각 입력칸이 생깁니다. 입력과 표시의 기준은 한국 시간입니다. 입력한 시각은 밀리초 타임스탬프로 저장하며, 비워둔 시각은 `null`로 저장합니다. 기록을 다시 열 때 비워둔 시각을 현재 시각으로 채우지 않으며, 조회 화면에서도 `미기록`이라고 표시합니다.

저장한 기록의 `수정`은 기존 `sessionId`를 보내 해당 기록을 교체합니다. 존재하지 않는 ID의 수정 요청은 거부하므로 새 기록으로 추가되지 않습니다. 수정 전후 다른 세션과 참가자 메모, 기존 종료 칩 등 입력 대상이 아닌 필드는 유지합니다. 참가자를 선택 해제하고 저장하면 해당 기록에서 그 참가자를 제외합니다.

입력 중 랭킹 정렬을 바꾸거나 서버 기록을 다시 불러와도 작성 중인 값을 유지합니다. 저장 실패 때도 입력을 복원해 다시 시도할 수 있습니다. 작성 중인 초안은 메모리에만 있으므로 브라우저 전체 새로고침까지 보존하는 기능은 아닙니다.

주간 우승은 한국 시간으로 월요일부터 일요일까지의 기록에서 계산하고, 누적 리바인은 모든 기간의 기록을 합산합니다. 날짜, 승리 횟수, 리바인 횟수를 수정한 뒤 랭킹을 다시 조회해 반영합니다. 홈 기록과 기존 테이블 주간 칩 장부는 각각 집계에 포함되므로 같은 게임을 양쪽에 새로 입력하면 별도 기록으로 합산됩니다.

기존 테이블 장부의 입력 검사는 실제 input에서 수행하도록 고쳤습니다. 9인 기록은 수정 ID까지 포함하면 기존 WebSocket 메시지 제한 1,024자를 넘었으므로 한도를 8,192자로 조정했습니다. 한도 초과 요청 거부는 유지하며 회귀 테스트로 확인했습니다. 장부 편집값은 실시간 상태가 갱신되어도 유지하고, 저장된 내용이 서버 상태에서 확인된 뒤 편집창을 닫습니다.

## 기존 저장 데이터에 미치는 영향

새 데이터베이스나 전체 변환 작업을 추가하지 않았습니다. 다음 식별자와 저장 키를 유지했습니다.

| 구분 | 유지한 값 |
| --- | --- |
| Worker | `river-friends-holdem` |
| Durable Object 클래스와 바인딩 | `PokerRoom`, `ROOMS` |
| Durable Object 네임스페이스 | `9d97cd87926241e4a0662e3541e06d78` |
| SQLite 마이그레이션 이력 | `v1`, `new_sqlite_classes: ["PokerRoom"]` |
| 회원 및 전체 랭킹용 Object 이름 | `river-members` |
| 테이블 저장 키 | `room` |
| 회원 및 랭킹 저장 키 | `registered-members`, `leaderboard-sessions`, `leaderboard-rooms` |

회원 연결이 필요한 기록에는 선택적인 `memberKey`와 `cohort`를 추가합니다. 새 기록은 회원 키로 집계해 이름이 같아도 기수가 다른 회원을 구분합니다. 테이블에 처음 연결한 회원 키도 유지해 같은 브라우저의 기존 전적을 다른 회원으로 바꾸어 재입장하지 못하게 합니다.

기존 `memberKey` 없는 기록은 원문을 일괄 수정하지 않고 현재 명단에서 이름이 처음 일치하는 회원에게 집계합니다. 명단은 기본 회원이 먼저이므로 기본 회원과 동명이인이 있으면 기본 회원이 우선됩니다. 기존 기록에 없던 기수는 추정해 채우지 않습니다. 같은 이름의 과거 기록을 어느 회원에게 연결할지까지 자동으로 판별하는 변경은 아닙니다.

기존 칩 단위 환산 함수와 게임 규칙은 그대로입니다. 이번 작업에서 환산을 다시 수행하는 별도 마이그레이션이나 운영 데이터 초기화 명령은 추가하지 않았습니다.

가이드를 포함한 최종 파일의 문법 검사와 배포 구성 검사가 통과했습니다. 로컬 검증은 `http://localhost:8791`과 격리 저장 경로 `/tmp/river-improvement-state`에서 진행했습니다. 검증 종료 후 8787 및 8791 서버를 정상 종료하고, 격리 저장소와 기존 로컬 `.wrangler/state`의 테스트 데이터만 삭제했습니다. 삭제 직전 목록을 다시 읽어 새 회원이나 기록이 추가되지 않았음을 확인했습니다. 테스트 코드와 fixture 소스는 유지했습니다.
