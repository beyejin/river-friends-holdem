# 기기별 사용성 검수

검수일: 2026-10-12

## 재현한 문제와 수정

- 모바일에서 6인 테이블과 베팅 버튼 사이가 길어 스크롤하면 상단 참가자가 보이지 않았습니다. 참가자를 위아래 3명씩 배치하고 테이블 높이를 줄였습니다. 390×844 화면에서 내 차례 행동 영역 하단이 약 914px에서 750px로 줄었습니다.
- 높이 768px 노트북에서 빠른 베팅 버튼이 화면 밖에 남았습니다. 이 높이에서는 테이블을 줄여 행동 영역 하단이 756.5px에 들어옵니다.
- 정보 탭을 누르면 전체 화면을 다시 그리면서 키보드 포커스가 사라졌습니다. 포커스를 복원하고 방향키, Home, End로 탭을 이동할 수 있게 했습니다.
- 같은 차례에서 갱신이 발생하면 입력 중인 베팅액이 초기화됐습니다. 같은 핸드, 라운드, 차례, 테이블 베팅액이면 유효한 입력값을 유지합니다. 차례나 최소 금액이 바뀌면 새 상태를 적용합니다.
- 초대 기능은 명시적인 링크 복사와 선택적인 공유 메뉴로 나눴습니다. 복사 실패 시 링크 선택과 수동 복사를 안내합니다. Escape로 닫으면 초대 버튼으로 포커스를 돌려줍니다.
- 입력 글자를 16px로 높이고 빠른 베팅 버튼 높이를 44px로 확보했습니다. 안전 영역 여백과 스크린 리더 차례 알림을 추가했습니다.
- 네트워크 복귀와 화면 재활성화 때 연결을 확인합니다. 응답 지연 시 재연결하며 베팅 명령을 자동으로 재전송하지 않습니다.

### 재현하고 수정한 문제

1. 512×384의 작은 가로 화면에서 본문 너비가 556px로 늘어 버튼이 잘렸습니다. 좌우 분할 배치를 600px 이상에만 적용했습니다. 수정 후 스크롤바를 제외한 화면 너비와 본문 너비가 모두 497px로 일치합니다.
2. Windows 고대비에 해당하는 `forced-colors: active` 조건에서 기본 버튼과 내 카드의 경계가 사라졌습니다. 시스템 색상을 따르는 테두리와 선택 표시를 추가했습니다.
3. 베팅액을 비우거나 최소 금액 미만으로 입력한 상태에서 탭을 전환하면 입력이 최소 베팅액으로 덮어써졌습니다. 같은 차례에서는 편집 중인 원문을 유지하고, `required`와 기존 최소 및 최대 금액 검증으로 잘못된 제출을 막습니다. 빈 문자열 유지와 `valueMissing`, 숫자 1 유지와 `rangeUnderflow`를 확인했습니다.

### 확인한 조건과 결과

Mac Chrome의 CDP로 해당 테스트 탭에만 화면 크기, 픽셀 배율, 모바일 레이아웃, 터치 입력을 적용했습니다. UA 문자열만 바꿔 다른 OS로 간주하지 않았습니다.

### 실기기 한계

- Windows VM, iOS Simulator, Android 에뮬레이터 또는 ADB는 이 환경에서 사용 가능한 설치를 찾지 못했습니다. 추가 유료 서비스나 대용량 가상 머신을 설치하지 않았습니다.
- iPhone 미러링은 실행했지만 Mac의 Touch ID 인증 화면에서 잠겨 있었습니다. 사용자가 직접 잠금을 해제하도록 요청했으며, 이번 검수에서 실제 iPhone 화면은 확인하지 못했습니다.
- Chrome으로 iPhone 화면 크기를 검사한 결과는 iOS Safari 엔진이나 실제 키보드, 공유 시트 검증이 아닙니다. Mac Safari의 실제 브라우저 검수 결과는 앞 절과 구분합니다.
- 화면 배율과 고대비를 적용한 Mac Chrome 테스트는 실제 Windows 및 Edge 실행 결과가 아닙니다.
- 참고: [Chrome Device Mode의 한계](https://developer.chrome.com/docs/devtools/device-mode#limitations), [Safari Responsive Design Mode의 범위](https://developer.apple.com/documentation/safari-developer-tools/responsive-design-mode).
